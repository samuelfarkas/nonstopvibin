# Storage and profile boundaries

Desktop and standalone development data default to `~/.nonstopvibin` on macOS and Linux. **Settings → Open data folder** reveals it. SQLite, `vault.key`, profile credentials/configs, and agent connection helpers live here; Electron uses `sessionData/` for browser storage and caches, `logs/` for app logs, and `crashDumps/` for crash dumps. `NONSTOPVIBIN_DATA_DIR` overrides this entire root; `NONSTOPVIBIN_PORT` overrides the default port 4318. Use a separate data override when testing alongside the desktop app.

To reset, quit the app completely (closing its window leaves it running), stop any development server using the same directory, delete the data folder, and reopen. No old location is automatically imported, so deleted accounts cannot reappear from an older installation. Earlier builds used `~/Library/Application Support/nonstopvibin` on macOS, normally `~/.config/nonstopvibin` on Linux, and repository-local `.runtime` in development. Those folders remain untouched.

Back up the data folder with the app fully stopped, keeping the database and its matching `vault.key` together. An existing database without its key is rejected; restore the matching key from backup. Generating a replacement cannot recover its secrets.

OS-managed login items, native agent configuration in other tools/projects, files you explicitly export, and external browser sign-in state are outside this folder. Disable launch at login and disconnect agents before deleting app data to remove those integrations. The agent credential broker also uses a private `/tmp/nonstopvibin-…` Unix socket directory because macOS limits socket path length; it stores no persistent account data. The installed application and OS-managed diagnostics remain managed by the operating system.

API keys and internal keys in SQLite are encrypted with AES-GCM using `vault.key` in the same data directory, in both desktop and development. The database and key are owner-only (0600 in a 0700 directory); software that can read both can decrypt the secrets. No system keychain is required. **The upstream process also needs plaintext credentials:** generated config and OAuth files are owner-only (0600 in 0700 directories), not encrypted while on disk. This is separation between account pools, not an OS security boundary against software running as your user.

The headless server (`nonstopvibin serve`, see [Run on a Linux server](server.md)) runs the same application without Electron, with desktop and development modes off. After it starts, it writes `server.json` (PID, port, session token, allowed hosts, version) atomically as an owner-only file in the data folder; `nonstopvibin url` and `status` read it and confirm an authenticated `/api/state` response, so a stale file or recycled PID is never reported as running. A clean shutdown removes the file only if it still names its own PID, and a second instance for the same data folder refuses to start. The token rotates with every process; `serve` includes it only when attached to a terminal, never in journald, while `url` prints it intentionally for session discovery. A missing core is fatal at startup, and the core's hash must match both its manifest and the pin compiled into the app. `--allow-host` adds one exact HTTPS host name (for example Tailscale Serve) for the web UI and management; the agent gateway and WebSockets still answer only on loopback.

The gateway binds only to 127.0.0.1. Agent keys cannot access management. Host/Origin checks protect local management requests. Provider sign-in uses the external browser and a state-validated loopback callback. The renderer has no Node access and only narrowly scoped desktop IPC.

Native agent connection files contain no profile credentials. Claude Code, Codex,
and pi obtain keys through their native credential command support. They use an
owner-only local Unix socket.
The socket has no management operations and is not reachable over TCP. Native
configuration fixes the profile URL; a port change requires reconnecting, and the
credential helper refuses to return a key for a different port. Existing settings
are preserved; conflicting edits are refused. Disconnect removes owned settings,
but does not revoke cached credentials: restart the agent, or stop the profile to
stop access. Software running as your OS user remains inside the trust boundary.
Legacy launcher files from earlier builds can still use the private broker; native
setup replaces the onboarding flow without deleting those existing files.

Request bodies, API keys, generated responses, and raw upstream error bodies are not written to the activity database. Accounting is drained approximately every two seconds around gateway requests, with a ten-second settling period for delayed publication and a thirty-second fallback while idle. Full queue pages and errors keep fast polling active. Stopping rejects new proxy requests and drains every queued accounting page before terminating the core. In-flight requests can be interrupted, and events not yet published by the core may be unavailable. The database survives restarts, but a crash between upstream completion, queue collection, and SQLite commit can lose accounting events; this is not a billing ledger. Activity shows/exports up to the most recent 500 records for its selected period; request totals, normalized token totals, and estimated API value cover the entire selected period. The all-time range includes all retained history. Provider quota reads occur approximately every two minutes while profiles run, and may be delayed by slow providers. After five minutes, previous readings are visibly stale.

Account and quota maintenance runs separately from accounting collection, so a slow provider does not delay draining usage. Unchanged account metadata does not rewrite SQLite. All-time usage summaries update only from committed inserts, avoiding a full history scan after every batch; replayed records and rolled-back writes leave cached totals unchanged. Optional activity retention deletes older records on apply, startup, and daily; aggregate totals then cover retained history. SQLite reuses freed pages without an automatic blocking vacuum.

The store caches only all-time profile summaries. Activity period summaries and prices share the aggregate described below, so ingestion and retention do not maintain a second period cache.

The background scheduler sleeps until the next accounting, maintenance, or cleanup deadline. Starting a profile or receiving gateway activity brings accounting forward; with no running profiles, only daily history cleanup remains scheduled. Display refresh timers stop while the interface is hidden and refresh immediately when shown. Sign-in polling continues while users complete authentication in their browser.

The main window and quota popup are created on demand and destroyed on close; unfinished main-window forms prevent unloading and hide instead. The proxy and menu bar remain available without a renderer. Tray status updates on process/activity changes, and the logo settles to static artwork after a finite opening or click animation. Core configuration enables upstream `commercial-mode` to skip request/response body logging middleware; this upstream option does not change the app's MIT license. Usage accounting remains enabled. Binary integrity verification streams the pinned core instead of reading it into one buffer.

A hidden window retries its deferred close when a draft or operation guard clears. Remaining forms and operation errors still prevent unloading, and reopening cancels the deferred close. Chromium's existing session caches fingerprinted UI assets; HTML and unhashed assets revalidate using ETags. Management responses remain `no-store`.

When migrating a refresh-token account, avoid running both apps against that same account during sign-in or token refresh. A provider may rotate the token, leaving the other copy outdated. Claude sign-in asks you to confirm the organization and destination profile before making the subscription available. Seats are distinguished by the provider's account and organization UUIDs, so the same email can connect to multiple organizations. Choose **Connect another organization** after connecting the first seat. Reconnecting the same seat preserves its connection ID, history, label, priority, and paused state; a running destination profile briefly restarts to safely replace its credential. A stopped profile stays stopped.

Duplicate detection is local to each profile: matching Claude seats, access/refresh tokens, and API credentials are rejected within that profile. The same subscription can be assigned to multiple profiles; requests then consume the same upstream subscription and independently stored OAuth credentials can become outdated after token rotation. Assign subscriptions deliberately when work and personal quota must stay separate. Older Claude files lacking those UUIDs display **Organization unverified** and are never merged by email; they must be connected separately and the obsolete entry removed. Other providers and unidentified legacy credentials can still represent the same upstream account, so assign those deliberately.

Full-period API values use the same validated provider-specific accounting and context-price tiers as individual records. Unknown prices or incomplete token breakdowns are reported as missing, never free. The server retains one aggregate per profile and processes at most 500 history rows before yielding to Electron's event loop. Unchanged refreshes read no history rows; new records add to the total and an advancing cutoff subtracts only newly expired records. Widening the period, retention, or a new model-price catalog rebuilds the aggregate. Calculations freeze the catalog for consistency and retain totals rather than history rows. Raw provider counters remain available in CSV; the displayed token mix uses non-overlapping counters and labels unclassified tokens explicitly.
